- **Site:** https://tools-websites-directory.pages.dev
- **Project:** `~/workspace/tools-websites-directory`
- **Audit date:** 26 Nov 2026
- **Auditor:** subagent (read-only audit; no files edited, nothing deployed, $0 spent)

- **Method:** parsed every prerendered HTML file in `frontend/dist` (title, meta, canonical, OG/Twitter, JSON-LD parsed with Python `json.loads`, H1–H3 counts, internal links, `<img>` tags); read `frontend/src/config/{site,seo,pages,sites-data}.js`, `src/components/SeoHead.jsx`, `Header.jsx`, `Footer.jsx`, all `src/pages/*.jsx`, `scripts/prerender.mjs`, `scripts/{generate-llms,generate-sitemap,generate-feed,validate-metadata,validate-links}.js`, `frontend/public/{robots.txt,sitemap.xml,llms.txt,llms-full.txt,feed.xml,_redirects}`; ran the project's own validators (`validate-metadata.js` → 0 errors, `validate-links.js` → 0 errors); compared against `~/workspace/scholar-jobs-hub`.

## Verdict in one paragraph

The stack is solid and better-instrumented than a typical Vite SPA: all 13 routes prerender with unique titles/descriptions, correct canonicals, valid JSON-LD on every page, exactly one H1 per page, a sitemap that matches the route manifest exactly, AI-crawler-friendly robots.txt, and genuinely complete llms.txt / llms-full.txt. There are **two blocking bugs** (a soft-404 page that canonicalises to `/sites` and is indexable, and duplicate WebSite+Organization JSON-LD on the homepage), one **stale-number problem** ("60+" everywhere while the directory actually lists 78 sites — including title, description, tagline, JSON-LD, feed and both llms files), and **no social-share image anywhere** (no `og:image` / `twitter:image` on any route, and no image asset exists to point one at). Everything else is should-fix or nice-to-have.

Findings:

- **(Blocking) Homepage duplicate structured data:** `frontend/index.html:22–28` hard-codes static WebSite + Organization JSON-LD "so crawlers see it without JavaScript". `scripts/prerender.mjs` (route `/` branch) then injects a *second* array `[websiteJsonLd(), organizationJsonLd()]` as a `data-prerender="1"` script. Result in `frontend/dist/index.html`: **3 JSON-LD scripts containing WebSite twice and Organization twice** (identical objects). The prerender strip regex only removes `data-prerender="1"` scripts, so the static pair survives on every page — harmless elsewhere, duplicated on `/`. Fix: for `/`, prerender should emit WebPage (+ BreadcrumbList) instead of re-emitting WebSite/Organization, or the static pair should be removed from `index.html`.
- **Homepage missing WebPage + BreadcrumbList in prerendered HTML.** The React `Home.jsx:21` *does* pass `webPageJsonLd(...)` to `SeoHead` client-side, but `prerender.mjs` route `/` sets `jsonLd = [websiteJsonLd(), organizationJsonLd()]` only — so a no-JS crawler never sees a WebPage object for `/`, and no BreadcrumbList exists for `/` at all. Every other route has WebPage + BreadcrumbList in the prerender.
- **BreadcrumbList is NOT missing anywhere else:** present on all 12 non-home routes, with correct `position`, `name`, absolute `item` URLs. Visible breadcrumb trails also render in React (`src/components/Breadcrumb.jsx`, used in About, Categories, Gaps, Search, Sites, Tier pages).
- **FAQPage exists only on `/about`** (3 questions, `scripts/prerender.mjs` ~line 249 and `About.jsx:33–39`) — correct and appropriate; no other page has FAQ content to mark up.
- ItemList counts match the data exactly: 78 on `/sites`; 8/18/34/8/3/7 per tier; sum 78. No fake reviews/ratings/prices in any JSON-LD (explicitly avoided in `SeoHead.jsx` comment; verified — no `AggregateRating`/`Review`/`offers` anywhere).
- Minor: `webPageJsonLd()` sets `inLanguage: "en"` and `<html lang="en">` (`frontend/index.html:2`) while the content is Roman Urdu. Same choice as ScholarJobs Hub; cosmetic, but a `ur-Latn`/`en` note would be more accurate.

## 11. Other findings (not in the 11-point list, found during audit)

1. **(Blocking) Soft-404 + wrong canonical on unknown URLs.** `src/pages/NotFound.jsx:7–11` renders `<SeoHead title="Page Not Found" path="/sites" …>` with **no `noindex`**. Consequences: (a) any unknown path emits `robots: index,follow`, a canonical pointing at `/sites`, and the title "Page Not Found | Tools Websites Directory" — an indexable page whose canonical claims it *is* `/sites`; (b) combined with `_redirects` (`/* /index.html 200`), unknown URLs return HTTP 200 with the homepage shell to no-JS clients — a classic soft 404. Fix: `noindex` + no canonical (or self-canonical) on NotFound, and ideally a real 404 status via a Cloudflare Pages `_headers`/function or by removing the catch-all for unknown paths. (ScholarJobs Hub was not checked for the same pattern — verify there too.)
2. **Google Search Console verification file not in the live build.** `frontend/public/googled5e63a81f27e9820.html` (53 B) exists in `public/` but is **absent from `frontend/dist/`** — it was added at 02:14, after the dist build at 02:01. Until the next build + deploy, Google cannot verify ownership via that file. (ScholarJobs Hub's identical file *is* present in its `dist/`.)
3. **Prerender/React content drift.** Prerender bodies are hand-written mirrors of the React pages and already drift: `/about` prerender has 2 H2s vs React's 5 (FAQ + Contact H2s missing in prerender); `/` prerender JSON-LD omits the WebPage object React adds. The `pages.js` header comment ("Keep in sync with those files") acknowledges the manual-sync risk. Low severity today, but it is how the next SEO bug will be introduced.
4. **`SITE_STATS.entries: 43`** (`sites-data.js:5`) vs 78 sites — "entries" is unexplained (43 ≠ 78 sites, ≠ 6 tiers); the homepage prerender prints "{sites} sites · {entries} entries" ("78 sites · 43 entries"). If "entries" means something real it should be labelled; if stale, remove it. Cosmetic.
5. **No `ads.txt`, no analytics config, no `theme-color`, no `apple-touch-icon`, no web manifest.** All absent here; ScholarJobs Hub has `ads.txt` and a config-gated (off-by-default) GA4 setup. Only `ads.txt`/analytics matter if monetisation/measurement is planned — otherwise fine to omit deliberately.
